## 4. Производительность CSS и JavaScript

Добавлена production-сборка публичных ресурсов:

- CSS объединяется и минифицируется в
  `public/assets/css/public.min.css`;
- JavaScript объединяется и минифицируется в
  `public/assets/js/public.min.js`;
- сведения о сборке сохраняются в
  `public/assets/asset-manifest.json`;
- сборка выполняется командой `npm run build:assets`;
- актуальность проверяется командой `npm run check:assets`;
- CI проверяет воспроизводимость сгенерированных ресурсов;
- установлены ограничения на допустимый размер Brotli-сборок.

Результат оптимизации:

| Ресурс | Без сжатия | gzip | Brotli |
|---|---:|---:|---:|
| CSS | 291 755 байт | 48 482 байта | 38 744 байта |
| JavaScript | 42 341 байт | 11 390 байт | 9 917 байт |

Количество основных локальных запросов CSS/JS сокращено с 9 до 2.
Суммарный объём основных ресурсов при Brotli-сжатии уменьшен примерно на 42%.

## 5. Настройки сжатия в административной панели

В раздел «Админка → Производительность» добавлена секция
«Сжатие CSS и JavaScript».

Она позволяет:

- включать оптимизированные CSS/JS-бандлы;
- временно переключаться на исходные файлы для диагностики;
- видеть активный режим загрузки;
- видеть состояние и актуальность сборки;
- видеть размеры CSS и JavaScript без сжатия, с gzip и Brotli;
- видеть наличие конфигурации Brotli и gzip на веб-сервере.

Добавлен класс `App\Core\FrontendAssets`, который является единой точкой
выбора публичных ресурсов.

Если manifest или production-бандлы отсутствуют либо повреждены, сайт
автоматически переключается на отдельные исходные CSS/JS-файлы. Это
предотвращает поломку публичного интерфейса из-за неполной публикации.

Сжатие HTTP-ответов выполняет веб-сервер:

- Brotli используется при наличии `mod_brotli`;
- gzip/DEFLATE используется как резервный вариант;
- PHP не выполняет повторное сжатие статических файлов.

## 7. Команды для локальной работы

Установка JavaScript-зависимостей:

```bash
npm ci
```

Пересборка CSS и JavaScript:

```bash
npm run build:assets
```

Проверка актуальности бандлов:

```bash
npm run check:assets
```

Проверка npm-зависимостей:

```bash
npm audit --audit-level=high
```

Перед публикацией необходимо обязательно выполнить:

```bash
npm ci
npm run build:assets
npm run check:assets
```

Сгенерированные файлы `public.min.css`, `public.min.js` и
`asset-manifest.json` должны быть загружены на сервер вместе с исходным кодом.

## 8. Что ещё требуется для production

Локальная работа завершена и проверки проходят. Для ввода изменений в
эксплуатацию ещё требуется:

1. Восстановить доступ к GitHub с двухфакторной аутентификацией.
2. Зафиксировать локальные изменения в Git отдельным проверяемым коммитом.
3. Создать резервную копию production-базы и пользовательских загрузок.
4. Развернуть код и сгенерированные бандлы на сервере.
5. Выполнить миграции базы данных, если их требует текущая production-версия.
6. Проверить права на `storage`, кэш и каталоги загрузок.
7. Проверить подключение к production-базе данных.
8. Выполнить smoke-проверку главной страницы, `/health` и `/admin/login`.
9. Проверить Brotli/gzip через заголовок ответа `Content-Encoding`.
10. Проверить журналы ошибок после развёртывания.

На момент аудита production-сайт, `/health` и `/admin/login` отвечали
HTTP 503. Это не связано с локальной сборкой CSS/JS. Вероятная причина —
подключение к production-базе данных или серверная конфигурация. Для точного
диагноза необходим доступ к конфигурации и журналам production-сервера.

## 9. Важное примечание

Работы выполнены в локальной копии. Изменения пока не отправлены в GitHub и
не развёрнуты на production-сервере. Итоговый ZIP является снимком исходного
кода на момент завершения локальных проверок и не содержит:

- каталога `.git`;
- `node_modules`;
- журналов и кэша;
- резервных копий;
- пользовательских загрузок;
- локальных секретов `.env`.

Обязательные пустые runtime-каталоги сохраняются в ZIP через файлы
`.gitkeep`. Установщик также автоматически создаёт недостающие каталоги
`storage/logs`, `storage/cache`, `storage/backups`,
`storage/protected_uploads` и `public/uploads/public`, если веб-сервер имеет
право записи в их родительские директории.
